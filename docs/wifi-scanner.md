# Wi-Fi 信号扫描

## 使用方式与显示内容

顶部选择“Wi-Fi”，点击“开始扫描 / 刷新”，允许精确位置权限，并开启系统 Wi-Fi 和定位开关。不需要连接目标网络。

- 显示 SSID、BSSID，同名接入点分别列出，按 RSSI 从强到弱排序。
- 信号强度直接展示 `ScanResult.level` 的原始 RSSI（单位 dBm），例如 `-57 dBm`，不换算成百分比或信号格。数值越接近 0，接收信号越强；它不是路由器发射功率，也不是网速。
- “类型”同时展示频段、协议和安全类型，避免含义不明确。频段包含 2.4 / 4.9 / 5 / 6 / 60 GHz；协议使用系统报告的标准，不根据频段猜测。Android 11 以下显示协议未知；设备未识别的标准也显示未知。
- 主信道由扫描结果的主频率换算，不是宽信道的中心信道；包含 2.4 GHz 信道 14 和 6 GHz 的 5935 MHz 特殊信道 2。未知频率不猜测信道。
- 安全类型解析系统 capabilities，支持 WPA/WPA2/WPA3 Personal、企业认证、WEP、OWE、WAPI 等。不能可靠细分的企业认证只标注 EAP，无法识别的能力显示未知。
- 每条结果展示距离采样的秒数，使用开机时间基准和 `ScanResult.timestamp`，不是把读取缓存的时间当作实际采样时间。

## 权限、限制与生命周期

使用 `ACCESS_WIFI_STATE`、`CHANGE_WIFI_STATE` 和运行时位置权限。精确与大致位置权限一起请求，仅获得大致位置时不会扫描。拒绝或永久拒绝后可使用“应用权限设置”；Wi-Fi 与定位开关各有设置入口。不申请后台位置权限，不上传扫描结果，不自动连接接入点。

主动扫描使用系统 `WifiManager.startScan()`。Android 会限制扫描频率，也可能因为设备状态拒绝请求；应用不绕过限制、不循环发起扫描。请求失败、结果未更新或等待超过 20 秒时明确标注缓存，避免将旧 RSSI 表述为最新测量。列表为空时给出提示。系统也可能广播其他扫描产生的结果，页面会读取系统结果并显示实际采样年龄。

扫描广播仅在 Wi-Fi 页面可见且 Activity 已启动时注册，离开页面或进入后台后注销并取消等待。结果仅保留在 Activity ViewModel 内，切换页面和旋转屏幕保留，进程结束后不保留扫描历史。设备支持、地区限制和系统扫描策略决定可发现的频段；识别频率不代表手机支持扫描所有频段。

## Windows / Android Studio 验证清单

该项目禁止在 WSL Codex 中执行构建。请在 Windows PowerShell（pwsh）中进入该项目目录，启动 Windows 环境下的 Codex，然后执行构建验证。

1. 同步并构建应用，运行 `WifiScanModelsTest` 单元测试和 `WifiScannerScreenTest` 仪器测试。WSL 中仅做静态检查，未执行这些测试。
2. 真机扫描 2.4 / 5 GHz 网络，确认 SSID、BSSID、频率、主信道、协议、安全类型和负数 dBm 正确；与路由器配置核对信道。设备支持时增加 6 GHz / Wi-Fi 6E / Wi-Fi 7。
3. 靠近和远离路由器，间隔一段时间手动刷新，确认 dBm 会随实际结果变化，列表按强度降序；多个同名 BSSID 不被合并。
4. 验证首次授权、拒绝、永久拒绝、仅大致位置、设置中改为精确位置；关闭 Wi-Fi、关闭定位及无 Wi-Fi 硬件时应显示明确提示。
5. 连续刷新触发系统限流时显示缓存提示，采样秒数继续增加；验证空结果与超时不会一直显示扫描中。必要时通过设备调试手段复现未更新广播与超时。
6. 扫描时切换标签、旋转屏幕、进入后台再返回，确认监听释放、按钮可重试、旧结果采样年龄不归零，其他工具不受影响。
7. 在 Android 7–10 检查协议未知的兼容路径，在 Android 11+ 检查标准识别，在 Android 12+ 检查精确位置授权和新版系统广播注册。
